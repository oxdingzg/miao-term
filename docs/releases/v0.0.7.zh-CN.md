# mtty v0.0.7

这是一个面向 Windows 的版本。v0.0.6 第一次能在 Windows 上启动;在一台真实的 Windows 11 桌面上测试它时发现了以下问题,
均已修复并在该机器上验证。macOS 与 Linux 的行为与 v0.0.6 相同。

## 修复(Windows)

- **切换输入语言会让 mtty 卡死。** 切换到中文输入法(或切回)后窗口永久停止响应。wgpu 探测了它的 OpenGL 后端,留下一个
  拥有隐藏窗口、却从不处理消息的线程;Windows 在切换语言时会通知所有线程的窗口并等待它们。现在 mtty 在 Windows 上只使用
  DX12 与 Vulkan(`WGPU_BACKEND` 仍可覆盖)。通过带符号的 minidump 定位。
- **SSH 会话无法启动。** mtty 输入到 cmd.exe 的所有 ssh 命令都会失败:POSIX 引号、`clear;` 以及 ControlMaster 选项。
  现在命令按 pane 的 shell(cmd 或 PowerShell)书写,并且不再使用 Windows 版 OpenSSH 不支持的 ControlMaster。涉及新建
  SSH 会话、已保存主机、重连以及在主机上执行片段。设为 *使用 mosh 连接* 的主机在 Windows 上改用 ssh(Windows 没有原生
  mosh 客户端)。
- **设置被忽略。** Windows 没有 `HOME`,所以 mtty 没有配置目录:`config.toml`、主机、片段、同步与会话都不起作用。现在它们
  位于 `%APPDATA%\mtty`(状态位于 `%LOCALAPPDATA%\mtty`);若在 Git Bash 的 `HOME` 下已有 `~/.config/mtty`,则继续使用它。
- **mtty 旁边会多开一个控制台窗口**,关闭它会连带关闭 mtty。
- **Quick Terminal 热键的按键会被输入**(Ctrl+Alt+Y 中的 Y)到新 pane:窗口获得焦点时仍按着的键不再被输入。
- **拖放的路径**使用单引号,cmd 中带空格的路径会被拆开;现在使用双引号。
- 重定向或在控制台中运行时,`mtty --version` 能正常输出。

## 验证

- 发布提交上完整的 macOS、Linux、Windows CI,以及四个 runner 的打包演练。
- 在真实的 Windows 11 桌面上:键盘输入、Tab 补全、菜单、微软拼音(预编辑、候选框位置、上屏)、反复切换输入语言、文件
  拖放、剪贴板(Ctrl+Shift+C/V)、Quick Terminal 热键、从 `%APPDATA%\mtty` 读取配置,以及新建 SSH 会话进入 ssh 的主机
  密钥确认提示。

## 已知限制

- 构建尚未经过 macOS 公证或 Windows 代码签名。
- mosh 只验证了命令构造;AppImage 与 Windows 的安装并重启辅助脚本有单元测试,但尚未在这两类桌面上实际运行。
