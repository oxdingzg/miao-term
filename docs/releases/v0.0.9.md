# mtty v0.0.9

Fixes found by checking the feature table against the code, a Software Update
dialog that filled the window, Edit in Tab, and a crash log.

## Fixes

- **Software Update filled the window's height.** The dialog stretched from the
  top of the window to the bottom, its title pushed off screen and its buttons
  in the middle. Its button row took all the height left on screen; it is now
  one row high. The other dialogs were checked for the same layout.
- **Markdown images next to the document did not show.** A relative path such
  as `![x](img/a.png)` never loaded in the preview; it now resolves against the
  document's folder. Absolute paths keep working; remote documents are
  unchanged.
- **View rules could not match a file.** A `views.json` rule with a `file`
  clause never fired and `{file}` in a title stayed empty. The file is now the
  one the foreground program opened (`src/main.rs` for `vim src/main.rs`), on
  macOS and Linux.
- **Agent details in Chinese.** The Agent tab's `agent` and `tty` keys and its
  state values (processing, idle, awaiting, error) were still English.

## New

- **Edit in Tab.** The built-in editor has an *Edit in Tab* button for local
  files: it opens a new tab running the `editor` setting, else `$EDITOR`, else
  `vi` (Notepad on Windows), as ADR 0017 specified. It is disabled while there
  are unsaved changes, since the external editor reads the file on disk.
- **Crash log.** A panic now appends its message, location and a backtrace to
  `~/Library/Logs/mtty/panic.log` (`~/.local/state/mtty` on Linux,
  `%LOCALAPPDATA%\mtty\logs` on Windows); the macOS app's stderr is discarded,
  so a crash used to leave no trace.

## Documentation

- The feature table in `docs/PRODUCT.md` was re-checked row by row against the
  code: problems fixed in earlier batches are no longer listed, and agent
  Resume and quota display, which do not exist, are listed as not designed yet.

## Verification

- Full CI on macOS, Linux and Windows, and the four-runner packaging, on the
  release commit.
- New tests: the update dialog's height (fails with the old layout), relative
  and absolute Markdown images loading through egui's file loader (the
  absolute case fails without the vendored patch), the foreground program's
  file from a real `tail -f`, Edit in Tab's command, and the Chinese Agent rows.
- The Software Update dialog was captured from the packaged macOS app.

## Known limits

- Builds are not notarized (macOS) or code-signed (Windows) yet.
- View rules' `file` matching is not available on Windows.
- mosh support is tested only as command construction; the AppImage and
  Windows install-and-relaunch helpers are unit-tested but have not run on
  those desktops.
