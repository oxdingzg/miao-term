# mtty v0.0.13

新增大文件只读查看模式:1 GB 的日志一秒内就能打开,占用内存很少。需要编辑时可以切换为可编辑,切换前会先告诉你要占用多少内存。

## 新增

- **超过 64 MB 的文件使用只读查看模式。** 大文件在编辑器 pane 中以只读方式打开,按屏从磁盘读取,所以文件再大,内存占用也很小。
  - 后台线程建立行索引;行号、选区、复制、滚动与编辑器一致,⌘↑ 和 ⌘↓ 跳到文件开头和结尾。
  - 查找在后台线程扫描整个文件,找到的数量逐步增加,扫描过程中显示"n / m…"。
  - 会话恢复时回到你正在看的那一行,仍是只读查看。
- **切换为可编辑。** 在只读查看模式下打字、粘贴、用输入法输入,或在命令面板选择**切换为可编辑…**,会弹出对话框:说明将把整个文件读入内存,
  以及需要多少内存,实测约为文件大小的 2.2 倍。确认后在后台线程加载,完成后 pane 变成普通编辑器,并停在原来那一行。
- **大文档查找。** 超过 8 MB 的文档在后台线程查找;超过 64 MB 时按整行分段读取,不再整篇复制。

## 修复

- **超过 64 MB 的文件会交给浮动编辑器打开**,浮动编辑器把整个文件读进一个文本框,1 GB 的文件可能让应用卡死。现在这类文件改用只读查看模式打开。

## 验证

- 发布提交在 macOS、Linux、Windows 上跑完整 CI,并完成四个 runner 的打包。
- **新增测试**:
  - 在文件任意位置读取一段行窗口;
  - CRLF、超长行与非法 UTF-8;
  - 跨块边界的搜索,每处匹配只报告一次(早期草稿会重复报告,这个测试在草稿上会失败);
  - 在 20,000 行中滚动窗口;
  - 只读查看模式下编辑被拒绝,保存也不会改动文件;
  - 按字节位置选中搜索结果;
  - 恢复到尚未建立索引的行;
  - 超过 64 MB 的文档分段查找。
- **性能门(Mac mini,release 构建),1 GB 文件,系统缓存已热**:

  | 步骤 | 耗时 |
  |---|---|
  | 首屏 | 1 ms |
  | 建立索引 | 0.3 s |
  | 读最后一屏 | 0.03 ms |
  | 全文查找 | 0.14 s |

- **用打包后的 macOS 应用截图验证**:
  - 打开 1 GB 日志用时 0.44 s,内存只多约 70 MB;
  - 会话恢复到第 5,000,000 行;
  - "切换为可编辑"对话框。
- **未截图验证**:在真实窗口中用键盘和滚轮滚动、查找,以及加载为可编辑。这些由单元测试覆盖;模拟真实按键需要辅助功能权限,构建机器没有授予。

## 已知限制

- 只读查看模式下,超过 64 KB 的行只显示开头部分,后面以省略号代替。
- 大文件不做语法高亮:tree-sitter 高亮的上限是 8 MB,Sublime 兜底高亮的上限是 1 MB。
- 超过 64 MB 的文档中,跨越约 4 MB 以上行范围的正则匹配找不到。
- 构建尚未公证(macOS),也未签名(Windows)。
