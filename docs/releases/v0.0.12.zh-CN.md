# mtty v0.0.12

本版本修复了编辑器 pane 的查找和终端输出问题,终端默认显示颜色,并支持大文件高亮。

## 修复

- **在查找框里打字会改动打开的文件。** 编辑器 pane 上打开查找(或命令面板、重命名输入框)时,每个按键也会发给编辑器:
  打字会替换文件里选中的文字,回车和退格会改动文件,在输入框里按 ⌘A 再删除会把整个文件清空。现在按键只交给有焦点的
  输入框。
- **在编辑器里查找,搜的却是终端**,结果显示 0 / 0。现在查找搜的是文档:按字面匹配,不区分大小写,与终端的查找一致。
  新的查找会选中光标处或之后的第一处匹配;回车、⇧回车以及"查找下一个/上一个"在匹配之间切换;"用选中内容查找"
  取编辑器里选中的文字。
- **不带颜色的 `ls` 各列错位。** alacritty 会在制表符跳过的第一个格子里存一个制表符;mtty 把它画了出来,字体给它
  一个制表符的宽度,同一行后面的内容就被挤偏了。现在这些格子按空白处理,屏幕显示、复制、搜索和恢复的终端内容都一样。
- **编辑器里的 Copy as ANSI 和 Copy Path。** Copy as ANSI 原来什么都不复制,现在复制选中的文字;Copy Path 原来复制
  所在文件夹,现在复制文件本身的路径。

## 新增

- **默认显示颜色。** 新开的 shell 带上 `CLICOLOR=1`,`ls` 不加 `-G` 或 `--color` 也会显示颜色。如果你已设置
  `CLICOLOR` 或 `NO_COLOR`,则按你的设置。程序只在输出到终端时才显示颜色,输出到管道或重定向到文件时仍为纯文本。
- **大文件高亮。** 超过 512 KB 的文件在后台线程解析:解析完成后显示颜色,编辑时颜色跟着更新,不会卡住打字。
  tree-sitter 高亮的上限从 1 MB 提高到 8 MB;上限由内存决定,因为语法树占用的内存约为文件大小的 25–35 倍。

## 验证

- 发布提交在 macOS、Linux、Windows 上跑完整 CI,并完成四个 runner 的打包。
- **新增测试**:
  - 输入框有焦点时的按键分发,以及 egui 的查找框会占住键盘;
  - 编辑器查找的起始位置;
  - 制表符所在格子按空白处理(显示、复制、快照与回放);
  - 默认颜色设置尊重 `CLICOLOR` 与 `NO_COLOR`;
  - 后台解析期间的编辑会补到新语法树上;
  - 8 MB 文件的性能门。
- **性能门(Mac mini,release 构建),8 MB 的 Rust 文件**:0.5 s 后显示颜色;每次按键在 UI 线程上耗时 0.009 ms;
  重新解析 127 ms 完成。
- **用打好的 macOS 包实际截图验证**:彩色的 `ls`、用制表符对齐的 `ls` 各列对齐、8 MB Rust 文件的高亮。
- **未经截图验证**:在编辑器上方的查找框里打字。模拟真实按键需要辅助功能权限,构建机器没有授予。

## 已知限制

- tree-sitter 高亮的上限是 8 MB,Sublime 兜底高亮的上限是 1 MB。
- 编辑器里的查找只支持按字面匹配;正则、区分大小写和全词匹配等选项留到后续阶段(E4)。
- 构建尚未公证(macOS),也未签名(Windows)。
