# mtty v0.0.12

[简体中文](v0.0.12.zh-CN.md)

Fixes for the editor pane's Find and for terminal output, colour by
default, and highlighting for large files.

## Fixes

- **Typing in Find edited the open file.** With Find (or the palette, or
  a rename field) open over an editor pane, every key also went to the
  editor. Typing replaced the file's selection, Enter and Backspace edited
  it, and ⌘A then Delete in the field emptied the file. Keys now stay with
  the focused field.
- **Find over an editor searched the terminal** and showed 0 / 0. Find now
  searches the document. It is literal and ignores case, like the
  terminal's Find. A new search selects the first match at or after the
  caret. Enter, ⇧Enter and Find Next/Previous step through the matches, and
  Use Selection for Find takes the editor's selection.
- **Plain `ls` drew its columns out of line.** alacritty stores a tab
  character in the first cell a tab skips; mtty drew it, and the font gave
  it a tab's width, which shifted the rest of the row. Those cells are now
  blank, on screen and in copied text, search and restored terminal
  contents.
- **Copy as ANSI and Copy Path in an editor.** Copy as ANSI copied nothing
  and now copies the selected text. Copy Path copied the folder and now
  copies the file's path.

## New

- **Colour by default.** New shells get `CLICOLOR=1`, so `ls` colours its
  output without `-G` or `--color`. An existing `CLICOLOR` or `NO_COLOR` is
  respected. Tools still colour only when writing to a terminal, so pipes
  and redirects stay plain.
- **Highlighting for large files.** Files over 512 KB are parsed on a
  background thread. Colours appear when the parse finishes and follow
  edits without blocking typing. Tree-sitter highlighting now goes up to
  8 MB, up from 1 MB; the limit is memory, because a parse tree takes 25–35
  times the file's size.

## Verification

- Full CI on macOS, Linux and Windows, and the four-runner packaging, on the
  release commit.
- **New tests:**
  - key routing with a focused text field, and egui's Find field holding
    the keyboard;
  - where an editor search starts;
  - tab cells reading as blank (drawn, copied, snapshot and replayed);
  - the colour default respecting `CLICOLOR` and `NO_COLOR`;
  - background parsing that replays edits made during a parse;
  - an 8 MB perf gate.
- **Perf gate (Mac mini, release build), 8 MB of Rust:** colours arrive
  after 0.5 s, a keystroke costs 0.009 ms on the UI thread, and the
  reparse settles in 127 ms.
- **Captured from the packaged macOS app:** coloured `ls`, aligned
  tab-separated `ls`, and an 8 MB Rust file highlighted.
- **Not captured:** typing into Find over an editor. Driving real
  keystrokes needs accessibility access the build machine does not grant.

## Known limits

- Tree-sitter highlighting stops at 8 MB, and the Sublime fallback at 1 MB.
- Find in an editor is literal text only; regex, case and whole-word
  options are still to come (E4).
- Builds are not notarized (macOS) or code-signed (Windows) yet.
