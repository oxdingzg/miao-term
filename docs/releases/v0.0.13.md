# mtty v0.0.13

View mode for large files: a gigabyte log opens in under a second and
uses little memory. If you need to edit it, you can switch, and you are told
what that costs first.

## New

- **View mode for files over 64 MB.** Large files open in an editor pane
  read-only and are read from disk a screen at a time, so memory stays
  small at any size.
  - A background thread indexes the line breaks. Line numbers, selection,
    copying and scrolling work as in the editor, and ⌘↑ and ⌘↓ go to the
    file's ends.
  - Find scans the whole file on a background thread. The count grows as
    matches are found and shows "n / m…" while the scan runs.
  - Sessions return to the line you were reading, still in view mode.
- **Switch to editing.** Typing, pasting or IME input in view mode, or
  **Switch to Editing…** in the command palette, opens a dialog. It says
  that the whole file will be loaded and how much memory that takes, about
  2.2 times the file (measured). The file loads on a background thread and
  the pane becomes a normal editor on the same line.
- **Find in large documents.** Documents over 8 MB are searched on a
  background thread. Over 64 MB, the search reads the text in windows of
  whole lines instead of copying all of it.

## Fixes

- **Files over 64 MB went to the floating editor,** which read the whole
  file into a single text field. A gigabyte file could freeze the app.
  They now open in view mode.

## Verification

- Full CI on macOS, Linux and Windows, and the four-runner packaging, on the
  release commit.
- **New tests:**
  - line windows anywhere in a file;
  - CRLF, overlong lines and invalid UTF-8;
  - search across chunk boundaries, reporting each match once. This test
    fails on an earlier draft that reported matches twice;
  - scrolling a window through 20,000 lines;
  - edits refused in view mode, and the file left untouched by Save;
  - search hits selected by their bytes;
  - a restored line beyond the indexed part;
  - windowed search of documents over 64 MB.
- **Perf gate (Mac mini, release build), 1 GB file, warm cache:**

  | Step | Time |
  |---|---|
  | First screen | 1 ms |
  | Index | 0.3 s |
  | Last screen | 0.03 ms |
  | Full search | 0.14 s |

- **Captured from the packaged macOS app:**
  - a 1 GB log opened in 0.44 s with about 70 MB more memory;
  - a session restored at line 5,000,000;
  - the Switch to Editing dialog.
- **Not captured:** keyboard and wheel scrolling, Find, and loading for
  editing in a real window. These are covered by unit tests; driving real
  keystrokes needs accessibility access the build machine does not grant.

## Known limits

- Lines longer than 64 KB show their start and an ellipsis in view mode.
- Large files show no syntax highlighting: tree-sitter stops at 8 MB and the
  Sublime fallback at 1 MB.
- In documents over 64 MB, a regex match spanning more than about 4 MB of
  lines is not found.
- Builds are not notarized (macOS) or code-signed (Windows) yet.
