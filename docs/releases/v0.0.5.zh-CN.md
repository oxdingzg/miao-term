# miaotty v0.0.5

本版本聚焦 CPU 使用、保留内存和持续终端输出下的正确性，包含共享工作区中的鼠标
协议、字形缓存修复，以及两轮输入路径性能优化。

## 主要改进

- 控制序列采用增量扫描，消除分片 Sixel/Kitty/iTerm2 payload 的二次方重复扫描。
  普通文字直接借用原始 chunk；OSC 元数据和光标查询共用有序输入事件流。
- PTY 每 pane 最多排队 256 KiB 数据，满队列施加背压；处理到 64 KiB 或约 4 ms 后
  在 chunk 边界让出 UI 并安排续调度，改善持续输出下的响应性。
- 按可见文字和字体布局缓存字形塑形，重复 CJK、滚动、改色及光标变化复用布局，
  释放过期布局；行构建和 ASCII 面板评分消除逐字符／逐条目的临时字符串。
- 可见图片动画按实际 100 ms 换帧时间重绘；视区外动画不安排定时重绘，新的视区外
  图片不上传 GPU。
- 解码复用 RGBA buffer，消除多余 base64／bitmap 副本，PNG 在解码像素前检查尺寸。

## 资源约束与修复

- 所有图片及动画帧的像素 buffer 实际容量合计最多 **128 MiB / terminal**；超额淘汰
  最旧的完整 placement，不对保留的动画帧重编号。
- 未完成 Kitty 传输实际容量合计最多 **32 MiB、16 个 ID**；超额丢弃当前传输。
  单动画最多保留 **256 帧**。这些是保留资源约束，不是整个进程的 RSS 上限；GPU
  texture、字体、scrollback 和解码临时内存另计。
- 完成或放弃大序列后释放扫描缓冲的高水位容量。
- 修复 drag／all-motion 鼠标协议遗漏按钮点击。
- 修复三个以上 Kitty 分片丢失中间 payload。
- 光标查询在此前文字更新光标后回复。
- 新图片淘汰旧图片时，仍正确执行请求的光标推进。

## 实测结果

与 v0.0.4 工作实现进行的本地 release 对照：

| 工作负载 | 优化前 | 优化后 |
|----------|--------|--------|
| 4 MiB 序列，512 B 分片 | 16,247 ms | 6.2 ms |
| 完整彩色文字输入路径 | 74.4 MB/s | 129.8 MB/s |
| 4 MiB 原始 RGBA 累计分配 | 23 次 / 24 MiB | 1 次 / 4 MiB |
| 真实宿主分片输出的应用 CPU 时间 | 5.90 s | 0.27 s |
| 40 张 1024×1024 PNG 的稳定 RSS | 427.91 MiB | 395.70 MiB |

结果针对相应工作负载，不是跨机器承诺，也不表示空闲功耗有相同比例的改善。
