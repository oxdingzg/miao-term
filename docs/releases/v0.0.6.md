# mtty v0.0.6

The first release under the name **mtty** (formerly miaotty), and the first one
built around the product roadmap: reliability work on what already shipped,
agent workflows, a host library with SSH/SFTP/FTP operations, and verified
updates. Website: <https://mtty.dev/mtty>.

## Upgrading from miaotty

- The application, command and bundle are now `mtty` / `mtty-cli` /
  `mtty.app` (bundle ID `dev.mtty.terminal`). On macOS install `mtty.app`; the
  old `miaotty.app` can be deleted afterwards.
- On first start mtty copies `~/.config/miaotty` to `~/.config/mtty` once. It
  still reads `MIAOTTY_*` variables, answers `miaotty://` links and the old
  control socket, and exports the old pane variables, so installed hooks and
  miao keep working. Details: [ADR 0032](../decisions/0032-rename-mtty.md).
- v0.0.5 only checks for updates, so update by downloading this release. From
  v0.0.6 on, mtty can download, verify and install updates itself (below).

## Highlights

**Agents**
- Launch Claude Code, Codex and other agents from mtty; copy ready-to-merge
  hook configurations for each.
- A prompt queue: a queued prompt goes to its pane when that pane's agent turns
  idle. Background tabs that need a look are marked, and notifications focus
  the right tab.
- Each command's output is captured through OSC 133: *Copy Last Command
  Output* and *Send Last Command Output to Composer*.
- Agent tasks in git worktrees: create, diff, merge or discard.

**Hosts and remote work**
- A host library (`~/.config/mtty/hosts.toml`, importable from
  `~/.ssh/config`) with groups, tags and jump hosts; host key checks, ssh-agent
  status and key setup — no passwords or keys are stored.
- Port forwards per host, an SFTP file browser, FTP/FTPS through the system
  `curl` (passwords stay in memory), and optional tmux/mosh persistent sessions.
- Command snippets that run here or on several hosts, and broadcast input to
  every pane of a tab.

**Platform**
- Verified updates: SHA-256 and a required minisign signature are checked in
  process, then *Install and Relaunch* replaces the app (macOS with rollback,
  AppImage, Windows MSI/zip).
- Shell integration for bash, fish and PowerShell alongside zsh (cwd, command
  boundaries, history), without editing your dotfiles.
- Optional end-to-end-encrypted sync of hosts and snippets through a folder you
  already sync (iCloud Drive, Dropbox, Syncthing). Off by default; no account,
  no server ([ADR 0033](../decisions/0033-encrypted-sync.md)).
- Linux and Windows shortcuts move to Ctrl+Shift (Alt+1…9 for tabs), leaving
  Super/Win to the desktop; see the README table.

## Fixes

- **Windows: mtty exited at start** with `No font data found for "cjk"` — the
  CJK font list had only macOS and Debian paths. It now uses the Windows system
  fonts (and more Linux locations) and never fails without one.
- **Tab** in the terminal no longer moves the UI focus to the File menu and
  swallows further typing.
- Native Wayland: dropping files now pastes their paths, and paste keeps
  working (GNOME serves one data device per client).
- Sidebars and in-app windows can be resized; network and process work stays
  off the UI thread; Enter submits dialogs, find and palettes; renamed tabs
  keep their names; the IME candidate window follows the terminal cursor.
- macOS: links opened from a browser or Finder reach mtty; restored SSH tabs
  offer to reconnect.

## Verification

- Full CI on macOS, Linux and Windows, and the four-runner packaging
  rehearsal, on the release commit.
- Desktop checks on a real Ubuntu 24.04 / GNOME 46 / Wayland session, with
  input injected through uinput: typing, menus, pinyin IME, file drops,
  clipboard, the new shortcuts, Tab completion, and a Quick Terminal hotkey
  through a GNOME custom shortcut (GNOME 46 has no GlobalShortcuts portal).
- On macOS, *Update and Relaunch* installed a test-signed package end to end,
  and tampered packages were refused.
- Windows 11: the startup fix was verified on a real desktop; the remaining
  Windows desktop checks (IME, drops, hotkey) are still in progress.

## Known limits

- Builds are not notarized (macOS) or code-signed (Windows) yet.
- Windows: on one machine mtty stopped responding after typing with a damaged
  third-party IME (Sogou Pinyin, whose own repair tool reported it broken).
  The cause is not confirmed yet; Microsoft Pinyin worked. Under investigation.
- mosh support is tested only as command construction, not against a real
  mosh-server. The AppImage and Windows install helpers are unit-tested but
  have not yet run on those desktops.
