# miaotty v0.0.5

This release focuses on CPU usage, retained memory, and correctness under
streaming terminal output. It includes the shared working-tree mouse and glyph
cache fixes alongside the input-path optimization passes.

## Highlights

- Incremental control scanning replaces quadratic rescanning of fragmented
  Sixel/Kitty/iTerm2 sequences. Ordinary terminal text is borrowed directly;
  OSC metadata and cursor-position queries share the ordered input stream.
- PTY output now applies backpressure at 256 KiB of queued payload per pane.
  Processing yields at chunk boundaries after 64 KiB or approximately 4 ms and
  schedules continuation, improving responsiveness under sustained output.
- Glyph shaping is cached by visible text and font layout. Repeated CJK spans,
  scrolling, recoloring and cursor changes reuse layouts; stale layouts are
  released. Row building and ASCII palette scoring avoid per-cell/entry strings.
- Visible image animations redraw at their actual 100 ms frame boundaries.
  Offscreen animations do not schedule timer-driven redraws, and new offscreen
  images are not uploaded.
- Image decoding reuses owned RGBA buffers, avoids unnecessary base64/bitmap
  copies, and checks PNG geometry before decoding pixels.

## Resource limits and fixes

- Retained pixel-buffer capacity is limited to **128 MiB per terminal**, including
  animation frames. Oldest complete placements are evicted when the budget is
  exceeded, preserving the numbering of frames that remain.
- Incomplete Kitty transfers are limited to **32 MiB of aggregate capacity and
  16 IDs**; a transfer that exceeds the budget is discarded. Each animation
  retains at most **256 frames**. These are retained-resource limits, not a
  process RSS cap; GPU textures, fonts, scrollback and decode temporaries are
  additional costs.
- Completed or abandoned large scanner buffers release their high-water
  allocation instead of retaining it for the life of the pane.
- Fix drag/all-motion mouse protocols omitting button clicks.
- Fix Kitty transfers with three or more fragments losing intermediate payloads.
- Reply to cursor queries after preceding text has updated the cursor.
- Preserve requested cursor advancement when a new image evicts an older image.

## Measured results

Local release comparisons against the v0.0.4 working implementation:

| Workload | Before | After |
|----------|--------|-------|
| 4 MiB sequence, 512-byte fragments | 16,247 ms | 6.2 ms |
| Full colored-text input path | 74.4 MB/s | 129.8 MB/s |
| 4 MiB raw RGBA allocation traffic | 23 calls / 24 MiB | 1 call / 4 MiB |
| Real-host fragmented-output app CPU time | 5.90 s | 0.27 s |
| 40 × 1024×1024 PNG, settled RSS | 427.91 MiB | 395.70 MiB |

These are workload-specific measurements, not cross-machine guarantees or a
claim of an equivalent idle-power improvement. Methodology and reproducible
commands are in [PERFORMANCE.md](../PERFORMANCE.md).

CI now runs scanner complexity and allocation gates alongside the existing
release budgets. `scripts/profile-input.py` provides isolated macOS CPU/RSS
profiles. Interactive desktop acceptance remains documented in
[RELEASE.md](../RELEASE.md).
