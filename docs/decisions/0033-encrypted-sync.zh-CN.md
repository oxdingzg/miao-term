# ADR 0033 — 可选的端到端加密同步(B4.5)

状态:已采纳。

## 背景

主机库与命令片段(M3)目前只存在单台机器上。Termius 通过自家云和账号同步;mtty 的原则排除了这种做法:
不要账号、不要 mtty 服务器、可读内容不离开本机,且该功能默认关闭。

## 决定

- **传输是用户本来就在同步的文件夹**(iCloud Drive、Dropbox、Syncthing、网络共享)。在 `config.toml`
  中设置 `sync-dir` 即开启同步;mtty 不连接任何服务器。
- **密钥。** 开启同步时在 `~/.config/mtty/sync.key`(权限 0600)生成一个随机 256 位密钥,它永远不进入
  同步文件夹。其他设备粘贴一次 *配对码*(`mtty-sync:` + 密钥的 base64url)即可加入。不用口令,也就无需
  调 KDF 参数。
- **加密。** XChaCha20-Poly1305(RustCrypto 的 `chacha20poly1305`,MIT/Apache-2.0),每次写入使用随机
  24 字节 nonce。文件格式为 `MTSYNC1\n` + nonce + 密文;用其他密钥生成的文件认证失败,会被报告,绝不合并。
- **每台设备一个文件。** 每台设备只写 `<sync-dir>/mtty-sync/<设备ID>.mtsync`,网盘客户端不会遇到两个写者
  写同一文件(不会产生"冲突副本")。读取时合并所有设备的文件。
- **按条目合并。** 条目是以名称为键的主机和片段,各带 `updated` 时间;删除记为墓碑。设备把当前文件与上次
  同步的状态比较,找出自己的改动,再合并所有设备的条目,新者胜(同时间按设备 ID 决定)。因此两台设备各自
  新增的主机都会保留;同一主机在两台设备上都改过时,保留较晚的修改。
- **安全。** mtty 在根据合并结果重写 `hosts.toml` 或 `snippets.toml` 之前,先把旧文件复制为
  `*.before-sync`。无法解析的文件绝不覆盖(与保存时相同)。
- **时机。** 启动时、每 60 秒、保存之后,以及 *立即同步* 时,作为后台任务运行。

## 后果

- 云端文件夹中无法读取用户主机的任何信息;丢失密钥只会失去读取文件夹的能力,不影响本地数据。
- 设备间时钟偏差可能让较早的修改胜出;对少量手动编辑可以接受,且备份保留了之前的文件。
- 目前只同步主机与片段;`config.toml` 仍按机器各自保存。
