# ADR 0014 — SSH 会话与远端 terminfo

> English (default): [`0014-ssh.md`](0014-ssh.md)

状态:已接受。

## 背景

M4(可选)希望 SSH 会话是一等公民:复用同一条连接、让远端终端表现与本地一致、且**绝不
要求远端装任何软件**。这是 roadmap 的最后一个里程碑,且是可选。

## 决定

`miaotty-app/src/ssh.rs` 提供各部件;面板动词 *New SSH Session…* 与 `ssh://` URL scheme
(ADR 0013)都使用它们。

- **目标解析**:`[user@]host[:port]`,支持 `[ipv6]:port`。
- **解析(ssh -G)**:解析 `ssh -G <dest>` 的 `hostname`、`user`、`port`,故尊重
  `~/.ssh/config` 别名;任何失败时原样使用输入值。
- **连接复用**:每个会话以
  `-o ControlMaster=auto -o ControlPath=~/.ssh/miaotty-cm-%r@%h:%p
  -o ControlPersist=60s` 启动,故首条连接会复用后续连接。
- **远端 terminfo + 零安装兜底**:`bootstrap` 本地运行 `infocmp -x`;若得到条目,则
  base64 编入远端命令,仅当远端 `infocmp <term>` 失败时才用 `tic -x` 安装到 `~/.terminfo`。
  若本地无该条目,则引导改为导出 `TERM=xterm-256color`。两种方式都 `exec $SHELL -l`,
  故会话就是普通登录 shell。

base64 在 crate 内实现(`base64_encode`)以避免依赖,并以标准 RFC 4648 向量覆盖。

## 后果

- 会话复用连接,且对**不支持 miaotty 的主机**也能工作,因为兜底就是普通 `xterm-256color`。
- 解析/命令是对字符串的纯函数,已有单测;真正的远端安装只能在真实主机上验证。
- 远端 MTP 的 `view`/`edit`、远端 agent hook,以及把 helper 引导到已知路径,仍属后续。
