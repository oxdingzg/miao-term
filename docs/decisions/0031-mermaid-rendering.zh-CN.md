# ADR 0031 — Markdown 预览里的 Mermaid

状态:已接受。

## 背景

内置 Markdown 预览里的 ` ```mermaid ` 代码块此前只显示“未渲染”占位。真正的 Mermaid 是庞大的
JS 库、依赖浏览器 DOM 测量,无法在进程内运行;而一个**半兼容**、会静默画错的渲染器,比诚实的
占位更糟(与 ADR 0029 同一原则)。

## 决定

两层,都在 `miao_term_ui::mermaid`:

1. **内置子集**(`parse` + `show`),覆盖最常见的形态:`graph` / `flowchart`,方向
   `TD|TB|BT|LR|RL`,节点 `id[Label]` / `id(Label)` / `id{Label}`(以及裸 id),边
   `-->` / `---` / `-.->` / `==>`,可带标签(`-->|text|` 或 `-- text -->`)并可串联
   (`A --> B --> C`)。按最长路径分层布局,用 `egui` 形状绘制。解析不了返回 `None`,调用方
   保留占位。
2. **可选外部渲染器**(`render_external`),仅在配置了 `mermaid-command`(如 `mmdc`)时使用。
   每个图只调用一次,把 PNG 缓存在会话文件旁边;工具缺失或失败则回退到 (1)。默认不设(不
   启动任何进程)。

两端预览都通过共享的 `miao_term_ui::markdown` 显示本地图片;原生预览因此也加了图片加载器。

## 影响

- 流程图离线可渲染,零新依赖、无许可风险。
- 其它图类型(时序、类图、甘特等)**不绘制**:显示占位;设了 `mermaid-command` 时由外部工具
  全量渲染。
- 子集在布局/样式上可能与真 Mermaid 不同,这一点明确记录而非隐藏;重要场合用外部渲染器兜底。
