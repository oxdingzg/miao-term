# ADR 0029 — 极小、可选的 vim 模式

> English (default): [`0029-vim-mode.md`](0029-vim-mode.md)

状态:已接受。

## 背景

内置编辑器是 `egui` 文本框。习惯 vim 的用户要求模态编辑,但"半兼容"的 vim 比没有更糟,而且对
其他用户它必须仍是一个普通文本框。

## 决定

一个**刻意很小**的 vim 模式,**默认关闭**(设 `editor-vim = true` 启用),实现为纯函数式的
按键→状态转换,因此有单测覆盖:

- 模式:`Normal` / `Insert`。`Escape` 回到 Normal;`i a I A o O` 进入 Insert(带通常的
  光标/行效果)。
- Normal 命令:`h j k l`、`0 $`、`w b`、`gg G`、`x`、`dd`、`u`(撤销),以及 `:w` / `:q`
  保存/退出。
- Normal 模式下**由应用持有缓冲区**:每帧丢弃 `egui` 自身的编辑,并按我们的状态放置光标,
  故打字不会破坏文件。Insert 模式就是普通编辑。
- 位置以**字符索引**表示;每次编辑重建文本(单次 O(n)),对阅读器既有的 2 MB 上限足够。

明确**不支持**(也不假装支持):寄存器、宏、计数、标记、搜索动作、文本对象、`p`,以及
`:w`/`:q` 之外的 ex 命令。

## 后果

- 不启用的人完全不受影响:`editor-vim` 为 false 时文本框行为与以前一致。
- 引擎(移动、编辑、切换模式、`:w`/`:q`)有单测;`egui` 接线(缓冲区归属、光标放置)是需要
  真人按键验证的部分,而它是可选的,故那里的粗糙不会影响正常编辑。
- 更完整的 vim 需要真正的编辑器控件而非文本框;本 ADR 不做此承诺。
