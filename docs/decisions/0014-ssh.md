# ADR 0014 — SSH sessions and remote terminfo

Status: accepted.

## Context

M4 (optional) wants first-class SSH sessions: reuse one connection, make the
remote terminal behave like the local one, and never require software on the
remote host. This is the last roadmap milestone and is opt-in.

## Decision

`crates/term-ui/src/ssh.rs` provides the pieces; a *New SSH Session…* palette verb
and the `ssh://` URL scheme (ADR 0013) both use them.

- **Target parsing**: `[user@]host[:port]` with `[ipv6]:port` support.
- **Resolution**: `ssh -G <dest>` is parsed for `hostname`, `user`, `port`, so
  aliases in `~/.ssh/config` are honoured; on any failure the typed values are
  used unchanged.
- **Connection reuse**: every session is launched with
  `-o ControlMaster=auto -o ControlPath=~/.ssh/miaotty-cm-%r@%h:%p
  -o ControlPersist=60s`, so the first connection multiplexes the rest.
- **Remote terminfo + zero-install fallback**: `bootstrap` runs `infocmp -x`
  locally; if it produces an entry it is base64-encoded into the remote command
  and installed with `tic -x` into `~/.terminfo` only when `infocmp <term>`
  fails remotely. If no local entry exists, the bootstrap exports
  `TERM=xterm-256color` instead. Either way it `exec`s `$SHELL -l`, so the
  session is a normal login shell.

Base64 is implemented in-crate (`base64_encode`) to avoid a dependency; it is
covered by the standard RFC 4648 vectors.

## Consequences

- Sessions reuse connections and work against hosts with no miaotty support,
  because the fallback is plain `xterm-256color`.
- Resolution/commands are pure functions over strings and are unit-tested; the
  actual remote install can only be verified against a real host.
- Remote `view`/`edit` over MTP, agent hooks on the remote, and helper
  bootstrapping to a known path are follow-ups.
