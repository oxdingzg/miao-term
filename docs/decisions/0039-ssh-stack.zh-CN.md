# ADR 0039 — 继续使用系统 OpenSSH 客户端

> English: [`0039-ssh-stack.md`](0039-ssh-stack.md)

状态:已接受。

## 背景

M6 R3 要决定 SSH 是否从系统 `ssh` 二进制改为 Rust 原生实现。mtty 一直调用 `ssh`
(ADR 0014):pane 运行该命令,因此 `~/.ssh/config`、`ProxyJump`、`ssh-agent`、主机
密钥提示与 ControlMaster 都由 OpenSSH 处理,mtty 通过 `ssh -G` 读取解析后的选项
(主机库、视图规则)。

原生客户端(许可宽松的候选是 `russh`,Apache-2.0)可去掉外部依赖、支持进程内 SFTP 与
端口转发,并给 Windows 一条不依赖 OpenSSH 的路径。代价是要重新实现一大片微妙的表面:
`~/.ssh/config` 的解析与全部选项语义、ProxyJump 链、agent 转发、主机密钥校验、连接
复用,以及各种密钥类型与算法——还要与用户本机已有的 OpenSSH 行为保持一致。

## 决定

**继续使用系统 OpenSSH 客户端。** macOS 与 Linux 都自带,Windows 10/11 也已随附;
ADR 0037 的字节管道终端意味着将来原生后端可以直接接入同一条 pane 路径,而不影响应用的
其余部分,因此等待没有损失。

只有出现下列情况才重新考虑:

- 需要支持一个没有 OpenSSH 的平台(不只是安装密钥);
- 需要 `ssh` 二进制无法提供的进程内 SFTP 或转发功能;
- 出现安全或维护上的理由,更倾向原生实现。

若要重做,候选是 `russh`;`ssh -G` 与保存主机的字段仍是唯一事实来源,使两种后端读取
同一份配置。

## 影响

- mtty 仍需要 `ssh` 二进制;安装器已把它当作运行时依赖,缺失时界面会提示。
- PPK 导入(ADR 0038)不受影响:它只在磁盘上转换密钥文件。
- 传输抽象(ADR 0037)是原生 SSH 后端将来的落点,而不是 pane 或会话模型。
- 现在不新增依赖;该决定隔离在传输层之后,易于回退。
