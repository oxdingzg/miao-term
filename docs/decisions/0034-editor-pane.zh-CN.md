# ADR 0034 — 原生编辑器 pane

> English (default): [`0034-editor-pane.md`](0034-editor-pane.md)

状态:已接受。

## 背景

mtty 目前在一个 egui 浮窗里编辑文件:一个基于 `String` 的 `TextEdit`,一个只覆盖六种语言的手写高亮器,没有多光标,没有
LSP,每次按键都要重新排版整个文件。目标是让 mtty 成为一流的文本编辑器——大文件也快、能高亮绝大多数语言、以键盘为先——
并且和终端位于同一套标签与分屏中,也就是 agent 与 shell 已经所在的地方。

编辑器的关键在内核(文本存储、编辑、撤销、语法分析)和渲染器,而不在 GUI 框架。mtty 已经自己绘制终端 pane(wgpu +
glyphon/cosmic-text,ADR 0030),并受性能门约束;egui 只画外围界面。换框架(GPUI、iced、Xilem)意味着重写外围界面,
编辑器内核仍要自己写。

## 决定

**编辑器是一种 pane,与终端平级**,由 mtty 自己的字形渲染器绘制,由现有的分屏树布局。

1. **pane 类型。** 一个标签同时持有终端 pane 与编辑器 pane(`Tab::panes`、`Tab::editors`);布局树按 id 指向任一种,
   保持不变,终端相关的代码路径因此原样不动。(实现说明,E2:这取代了原计划的 `PaneContent` 枚举,后者会改动全部 66 处
   `pane.term` 调用。)会话条目增加带路径、光标与滚动位置的 `editors`;MTP `pane.list` 报告每个 pane 的 `kind`。发给编辑器的
   `pane.send`/`pane.run` 在其光标处插入文本(一个撤销步骤);`pane.close` 不会关闭有未保存修改的编辑器。
2. **不依赖 GPU 的内核 crate `term-editor`。** rope(`ropey`)缓冲区;带撤销/重做历史的事务;多选区;基于 rope 的搜索
   (`regex`);换行符与 UTF-8/BOM 识别;外部修改时重新加载。纯函数,有单元测试和独立的性能基准。
3. **用 tree-sitter 做语法。** 每次编辑后增量重新解析,只高亮可见范围;内置一组语法(起步约 20 种),高亮查询映射到 mtty
   主题,未知文件为纯文本。同一棵语法树以后还用于折叠、大纲与结构化选择。不选 syntect,因为它要从文件开头重新高亮,也没有
   语法树。(实现说明,E3:内置 80 种语法,每种都用其 crate 自带的高亮查询;macOS 二进制从 20 种语法时的 39.8 MB 增至 87.8 MB。没有语法认领的文件
   退回到 syntect 的 Sublime 语法:syntect 默认语法集,加上从 bat 引入的宽松许可语法,每 64 行保存一个解析检查点,
   逐行解析。超过 512 KB 的文件在后台线程解析,解析期间的编辑会补到新语法树上;语法树占用的内存约为文件的 25–35 倍,因此 tree-sitter 高亮止于 8 MB,Sublime 兜底止于 1 MB。(实现说明,大文件:超过 64 MB 的文件以只读查看模式打开,
   直接从磁盘读取:后台线程每 1024 行记录一次行首位置,pane 的文档是约 3000 行的窗口,随滚动移动,所以选区、复制和绘制都沿用
   编辑器自己的实现。编辑前先询问,确认后读入整个文件,并说明需要的内存,实测约为文件大小的 2.2 倍。)各语法的许可见
   `docs/third-party/SYNTAXES.md`。)
   (实现说明,E6:折叠依据语法树——任何跨行的命名节点,按起始行取最外层;没有语法树或没有这样的节点时退回按缩进。行号栏显示
   ▸/▾,折叠后的首行末尾显示 ⋯,上下移动跳过被隐藏的行,⌥⌘[ / ⌥⌘] 折叠/展开,命令面板提供“全部折叠/全部展开/切换折叠”。大纲
   列出定义型节点(函数、类、结构体、枚举、trait/接口、impl、模块、常量、类型、变量、宏),取节点的 `name` 字段并按层级缩进;
   ⌘R 打开可过滤的选择器。)
4. **复用终端的渲染管线。** 编辑器把可见行构建成等宽单元格网格上的带样式文字段(Tab 展开、宽字符占两格),外加行号栏、
   选区与光标的矩形。`term-render` 增加逐段样式(粗体、斜体、下划线),并把字形裁剪到 pane 内(目前只裁剪到窗口)。只构建
   可见行,所以 100 MB 的文件与一屏内容开销相同;性能门新增一项,保证在 4 ms 帧预算内。
5. **输入。** 按键交给当前 pane 的类型处理。默认键位遵循 macOS 文本习惯(方向键、⌥ 按词、⌘ 按行、⇧ 选择、⌘Z/⇧⌘Z、
   ⌘F、⌘D 选中下一个相同项、⌥ 点击添加光标),其他平台用 Ctrl 对应;输入法预编辑在光标处内联显示,与终端一致;vim 模式
   在后续阶段迁移过来。(实现说明,E6:vim 模式是 `term-editor` 中作用于文档的状态机——NORMAL/INSERT/VISUAL/VISUAL LINE,
   计数,`h j k l w b e 0 ^ $ gg G`,`i a I A o O`,`x`,`d`/`c`/`y` 配合动作(`dd`/`cc`/`yy`、`dw`、`d$`),`p`/`P` 配内部寄存器,
   `u` 与 Ctrl-r,`J`;`/` 与 `:` 交给宿主的查找栏与一个小命令行(`:w`、`:q`、`:wq`、`:<行号>`),`za`/`zo`/`zc`/`zR`/`zM` 操作折叠。
   状态栏显示当前模式。由 `editor-vim` 配置项开启。)
6. **文件。** 文件面板、Open Quickly、`app.edit`、拖放与 Hint 模式都打开编辑器 pane(新标签,或按修饰键分屏)。未保存
   状态显示在标签上;关闭时询问。远端文件沿用 ssh 读写路径。
   (实现说明,E3 远端文件:远端文件对话框在后台任务里经 ssh 读取字节并在编辑器 pane 中打开;`⌘S` 与 vim `:w` 以同样方式写回,
   写入期间若又发生编辑,面板保持“已修改”(`:wq` 等写入落地后再关闭)。远端 pane 不保存本地磁盘戳,因此跳过外部变更轮询;
   不启用语言服务器(它的路径在主机上,不在本地磁盘),也不启用查看模式;标题为 `主机:文件名`。会话保存目标与路径,恢复时
   重新从主机读取。)
   (实现说明,E6:打开的 pane 记住文件长度与修改时间,约每秒
   重新检查一次。没有未保存修改时,原地重载为一个可撤销事务,只替换有差异的片段并把光标映射过去,面板恢复为“未修改”;
   有未保存修改时,mtty 询问是从磁盘重载还是保留本地版本。文件在面板下被删除时提示一次。超过 64 MB 的只读查看 pane 不处理。)
7. **LSP 放在后面**,按工作区根目录经 stdio 运行:诊断、悬停、补全、跳转定义,在 `config.toml` 中按语言配置。
   (实现说明,E5:不依赖 GPU 的 crate `term-lsp` 只用 serde_json,经服务器的 stdio 收发 JSON-RPC。每个语言组与工作区根目录
   (最近的含项目文件的目录,否则是含 `.git` 的目录)各运行一个服务器;启动、初始化与读取都在后台线程完成,并在登录 shell
   的 `PATH` 中查找程序(从 Dock 启动的应用没有这个 PATH)。每次修改都以不带范围的 `textDocument/didChange` 同步全文,
   让客户端保持简单且正确;超过 2 MB 的文件不启用服务器。位置编码优先协商 UTF-8,否则用 UTF-16。诊断在对应单元格下画线并
   在状态栏计数;指针停留 450 ms 后显示悬停信息;补全在输入触发字符、输入单词时或按 Ctrl+Space 时打开,在客户端过滤,片段
   以纯文本写入、光标落在第一个占位符,并一起应用附加编辑(如 import);F12 或 ⌘ 单击跳转到定义,F8 跳到下一个问题。默认
   支持 rust-analyzer、typescript-language-server、pyright、gopls 与 clangd,可在 `config.toml` 的 `[lsp]` 中覆盖。已用
   rust-analyzer 1.94 与 typescript-language-server 5.3(TypeScript 5.9)验收。)
8. pane 覆盖现有功能后,下线浮窗编辑器;Markdown 预览改为编辑器旁边的预览 pane。(实现说明,E4:标签在终端与编辑器之外
   持有 `previews`,布局树同样按 id 指向它们。预览随输入实时显示所属编辑器的文本,由 egui 在 pane 卡片内、背景层中渲染,
   因此对话框始终在其上方;关闭编辑器会一并关闭它的预览,会话会保存预览。本地 Markdown 文件在编辑器 pane 中打开,右侧附带
   预览;浮窗只保留给只读查看(`app.view`),待它迁到 pane 后再下线。编辑器中的查找增加区分大小写、全字匹配、
   正则与替换;macOS 应用中,与编辑器按键相同的菜单快捷键(⌘D、⇧⌘Z、⇧⌘L)在编辑器有焦点时按下会交给编辑器,按 AppKit
   当前处理的事件区分按键与鼠标点击。)

## 阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| E1 | `term-editor` 内核:rope、事务、撤销、选区、搜索 | 单元测试;100 MB 文件上的编辑/搜索基准 |
| E2 | 编辑器 pane MVP:pane 类型、带样式文字段与裁剪、键盘、鼠标、输入法、剪贴板、打开/保存/关闭、会话恢复 | 回放测试;真实窗口截图;行构建的性能门 |
| E3 | tree-sitter 高亮(80 种语言,更多语言由 Sublime 语法兜底)、大文件模式、远端文件 | 高亮快照测试;大文件上的按键延迟 |
| E4 | 多光标、查找替换、跳转到行、Markdown 预览 pane | 回放测试 |
| E5 | LSP:诊断、悬停、补全、跳转定义 | 用 rust-analyzer 与一个 TypeScript 语言服务器验证 |
| E6 | pane 中的 vim 模式、基于语法树的折叠与大纲、外部修改重新加载 | 回放测试 |

## 后果

- 新依赖:`ropey`、`regex`、`tree-sitter` 及各语言的语法 crate(C 代码,在各平台工具链上用 `cc` 编译),以后还有 LSP
  客户端。语法与查询文件的许可按 ADR 0006 逐个核对。
- 渲染器保持等宽;比例字体与富文本不在范围内。
- pane 不再全是终端:广播输入、MTP `pane.send` 与只读模式对编辑器 pane 的行为需要明确(E2)。
